Trust & Security

How we handle your data

Last updated 2026-07-26. This page is derived directly from our internal engineering security review and is kept in sync with it — not marketing copy written separately from what the code actually does.

Where we are today: DataFe is in early access. We're honest that this means no SOC 2 report and no completed third-party penetration test yet — both are on our roadmap before we ask anyone to run production PII through a self-hosted or hosted instance at scale. Everything below is independently true right now; nothing here is aspirational or "coming soon" phrased as if it already shipped.

Tenant isolation

DataFe is multi-tenant. Every query that touches your organization's data filters by organization ID at the database layer, and this is verified by dedicated automated tests that specifically check for cross-organization data leakage, not just happy-path access.

Authentication & access control

  • JWT-based session auth (HS256), signed with a required application secret — the app refuses to start without one configured, so there's no silent insecure default.
  • Passwords are hashed with PBKDF2-SHA256, never stored in plaintext.
  • Per-account lockout after 5 failed login attempts within 15 minutes, to blunt brute-force attempts.
  • Passwordless "magic link" login is available as an alternative to passwords entirely.
  • Role-based access control with four roles (Admin, Steward, Data Owner, Viewer) enforced on every mutating API endpoint — admin-only actions are actually admin-gated, not just hidden in the UI.

Open Single sign-on (SSO/SAML) is not yet available. It's on our near-term roadmap and required reading if SSO is a hard requirement in your own security review.

Encryption

  • Data source connection credentials (e.g. a warehouse password you connect DataFe to) are encrypted at rest before they ever touch the database — verified by a test that reads the raw database file and confirms the plaintext credential never appears in it.
  • Traffic to and from the app should always run over HTTPS in any real deployment (self-hosted instances behind a tunnel or reverse proxy should terminate TLS there).

What we store from your connected sources

Connecting a data source (a database, warehouse, or file) lets DataFe read schema metadata (table/column names, types, relationships) and, for cataloging purposes, a limited number of sample values per column so the catalog is actually useful to search. We do not ingest or store your full datasets. See our Privacy Policy for more detail on data handling.

Sub-processors

If you enable the AI-powered "Ask" assistant with your own Anthropic API key, questions and relevant catalog context are sent to Anthropic's API to generate answers. This is opt-in — the feature works in a reduced, keyword-matched mode with no external calls if no key is configured. We don't use any other third-party processor for your catalog data today.
